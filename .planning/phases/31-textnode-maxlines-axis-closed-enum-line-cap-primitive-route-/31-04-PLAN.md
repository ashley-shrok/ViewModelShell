## 9.2.0 — 2026-08-03 (npm + NuGet aligned)

Additive minor: adds the `TextNode.maxLines` closed-enum axis for single-line ellipsis (`1`) and 2- or 3-line clamp (`2 | 3`). Motivated by Angel's `/ai` sidebar session titles (2026-08-03), which hand-truncated server-side via `.Substring(0, 16) + "…"` because VMS shipped no wire knob — this closes that gap for every future consumer with the same shape.

### Added

- **`TextNode.maxLines?: 1 | 2 | 3` axis** — closed-enum optional field on the `TextNode` interface (`viewmodel-shell/src/index.ts`) with a byte-parallel `int? MaxLines` positional slot on the .NET twin (`viewmodel-shell-dotnet/ViewModels.cs`), guarded by `[JsonIgnore(WhenWritingNull)]` per gotcha #8. `1` renders single-line ellipsis via `text-overflow: ellipsis`; `2` and `3` render 2- and 3-line clamp via `-webkit-line-clamp`. Absent = current wrap behavior unchanged (backwards-compatible).
- **Composes for free into every composite carrying a TextNode slot** — `UserRowNode.name`, `ListRowNode.primary`/`secondary`, `MessageNode.content`, `TimelineEntryNode.description`, `DetailRowNode.label`/`value`, `ChipNode.label`, and standalone TextNode. The axis lives on TextNode; consumers pass `TextNode(value, maxLines: N)` into any composite slot that accepts a ViewNode. No composite renderer changed in this release.
- **Shipped CSS rules** in `viewmodel-shell/styles/default.css` (3 rules): `.vms-text--max-lines-1` (single-line ellipsis), grouped `.vms-text--max-lines-2, .vms-text--max-lines-3` (line-clamp base), and per-value `-webkit-line-clamp: 2` / `-webkit-line-clamp: 3`. No theme change; no `--vms-*` token; `check:aa-contrast` untouched (layout axis, not color).
- **Cross-backend parity fixture** — `parity/fixtures/textnode-maxlines.json` (4 steps: unset + 1 + 2 + 3) with per-step `expectBodyContains` tripwires per AGENTS.md gotcha #9 class-3 lesson, byte-diffed across the 3 FeatureProbe backends.
- **Framework tests** — `viewmodel-shell/test/text-max-lines.test.ts` (renderer + shipped-CSS grep + composition) and `viewmodel-shell-dotnet/Tests/TextMaxLinesSerializationTests.cs` (emission per value + WhenWritingNull direct-assertion + round-trip).

### Deferred

- **`TableColumn.maxLines?`** — table cells are `Record<string, string>`, not ViewNodes; can't flow this axis through without a separate `TableColumn.maxLines?` field. Follow-on if a consumer surfaces the need.
- **Middle-truncate axis** (`abcdef…xyz`) — no pure-CSS mechanism; would need a JS-based follow-up primitive if requested.
- **Auto-wire `TooltipNode` on truncation** — container width isn't knowable at wire time; consumers who need an a11y-honest reveal compose `TooltipNode` explicitly around the TextNode. Same posture as MUI + Ant.
- **Values 4+** — closed enum stops at 3; a shape needing 4+ lines is a content problem, not a truncation problem.

### Consumers

**No action required.** Rebuild against 9.2.0 and pass `maxLines: N` on any TextNode where you want line-clamping — including inside any composite carrying a TextNode slot (UserRowNode.name for Angel's sidebar case; ListRowNode.primary for a title cap; MessageNode.content for a summary; etc.). No API change; no breaking wire. Package moves: npm `@ashley-shrok/viewmodel-shell` MINOR bump (9.2.0); NuGet `AshleyShrok.ViewModelShell` MINOR bump byte-parallel. Companion `AshleyShrok.ViewModelShell.Markdown` NOT affected (MINOR core bump; the 'core MAJOR bump requires companion rebuild' rule does NOT fire on MINOR).

---

```markdown
## Upgrading to v9.2.0

v9.2.0 is an ADDITIVE minor bump — one new optional field (`TextNode.maxLines?: 1 | 2 | 3`), no wire break, no runtime behavior change for existing apps.

### What consumers get for free

- **Rebuild against 9.2.0** and every existing `TextNode` continues to render exactly as before — `maxLines` is optional and absent by default.

### What consumers might want to do

If your app has a title/summary/label somewhere that overflows its container and you were hand-truncating server-side (e.g. `.Substring(0, 16) + "…"`) OR you were composing a bespoke CSS class in a demo-style hack: replace with the axis.

**Example — Angel's `/ai` sidebar session titles**:

```typescript
// Before (hand-truncated server-side):
new TextNode(BuildSessionLabel(session)); // .Substring(0, 16) + "…"

// After (framework-provided):
new TextNode(session.Title, maxLines: 1); // single-line ellipsis, framework-owned
```

The axis composes into every composite carrying a TextNode slot — pass `TextNode(value, maxLines: N)` into `UserRowNode.name`, `ListRowNode.primary`, `MessageNode.content`, `TimelineEntryNode.description`, `DetailRowNode.label`/`value`, or `ChipNode.label` for the same effect. No composite renderer changed in this release.

**Truncation-aware Tooltip is NOT auto-wired** — consumers who need an a11y-honest reveal on truncation compose a `TooltipNode` explicitly around the TextNode. Same posture as MUI + Ant.

**Values outside `1 | 2 | 3` are out of scope** — the closed enum stops at 3 (content longer than that is a content problem, not a truncation problem). Middle-truncate (`abcdef…xyz`) is also out of scope (no pure-CSS mechanism). Both can be surfaced as follow-on bounties if a real consumer needs them.

### What consumers CANNOT do

- **Table cells** — `TableRow.cells` is `Record<string, string>`, not ViewNodes; the maxLines axis doesn't reach into cells. A separate `TableColumn.maxLines?` field would be a follow-on; not shipped in v9.2.0.

Package moves: npm `@ashley-shrok/viewmodel-shell` 9.2.0 MINOR; NuGet `AshleyShrok.ViewModelShell` 9.2.0 MINOR byte-parallel. Companion `AshleyShrok.ViewModelShell.Markdown` NOT affected (no rebuild required — MINOR core bump, not MAJOR).

---
```
