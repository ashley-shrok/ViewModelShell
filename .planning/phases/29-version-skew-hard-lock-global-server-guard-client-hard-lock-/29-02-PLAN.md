    ```csharp
    /// <summary>
    /// 9.0.0 (SKEW-01) — global ACTION filter (twin of <see cref="ShellVersionResultFilter"/>)
    /// that fail-closes any incoming request (GET + POST) whose
    /// <c>X-VMS-Client-Build</c> header does not match the server's current-deployed
    /// build, BEFORE any controller runs. Twins the per-controller
    /// <c>ActionPayload&lt;T&gt;.Parse(HttpRequest, currentBuild)</c> overload's semantics:
    /// absent header → pass through (agent-driven curl still works); empty
    /// <see cref="VmsVersioningOptions.CurrentBuild"/> → inert (versioning off);
    /// header matches → pass through; header mismatches → throw
    /// <see cref="StaleClientException"/> so <see cref="ShellExceptionFilter"/>
    /// maps it to the byte-identical 400 <c>stale_client</c> envelope (no new
    /// envelope path, no new error code). Self-registered by
    /// <see cref="VmsVersioningExtensions.AddVmsShellVersioning(IServiceCollection)"/>
    /// alongside <see cref="ShellVersionResultFilter"/>.
    /// </summary>
    public sealed class ShellVersionGuardFilter : IActionFilter
    {
        private readonly VmsVersioningOptions _options;

        public ShellVersionGuardFilter(VmsVersioningOptions options)
        {
            _options = options;
        }

        public void OnActionExecuting(ActionExecutingContext context)
        {
            var current = _options.CurrentBuild;
            if (string.IsNullOrEmpty(current)) return; // versioning off → inert
            var advertised = context.HttpContext.Request.Headers["X-VMS-Client-Build"].ToString();
            if (string.IsNullOrEmpty(advertised)) return; // absent header → pass through (agent-driven testing)
            if (advertised == current) return; // match → happy path
            // Mismatch → throw StaleClientException so ShellExceptionFilter maps to
            // the byte-identical 400 stale_client envelope. Same exception the per-
            // controller Parse(HttpRequest, currentBuild) overload throws, so wire is
            // identical between global guard and pre-existing per-controller guard.
            throw new StaleClientException(advertised, current);
        }

        public void OnActionExecuted(ActionExecutedContext context) { }
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → global action filter | Every request passes through the guard BEFORE any controller runs. A bug in the guard (e.g., accidentally throwing on the happy path, or failing to throw on mismatch) has fleet-wide impact — every controller in the app is behind it. |
| Reused exception mapping | The guard throws StaleClientException instead of setting `context.Result` directly. Correctness depends on ShellExceptionFilter's mapping being STABLE. A regression in ShellExceptionFilter (unlikely — the mapping is shipped since v3.8.0) would silently break the wire on both the guard AND the per-controller Parse path. Cross-backend parity fixture (Plan 29-07) is the tripwire. |
| Filter dedup guard | Two filter registrations would throw twice on a mismatched request — one 400 stale_client + one uncaught exception in the second run. The dedup on `TypeFilterAttribute.ImplementationType == typeof(ShellVersionGuardFilter)` prevents this. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-04 | Tampering | X-VMS-Client-Build header spoofing | accept | An attacker CAN spoof the header to advertise any build id. Spoofing the CURRENT build lets them bypass the guard (same as any client), so this is not a new vulnerability — the guard's job is not authentication but consistency. A stale client cannot ELEVATE by spoofing (the state they submit is still validated by the controller). |
| T-29-05 | Denial of Service | Guard throws per-request → constant exceptions in log | mitigate | The guard only throws on ACTUAL mismatch (a stale client), which is a bounded, self-limiting condition (the client hard-locks per Plan 29-03/06 and reloads). No amplification vector. ShellExceptionFilter's mapping is a plain response envelope, not a stack trace to the client (verified in shipped v3.8.0 behavior). |
| T-29-06 | Information Disclosure | StaleClientException.Message leaks build IDs | accept | The message names both `advertised` (client-supplied) and `current` (server-deployed) build IDs. Both are already advertised — `X-VMS-Client-Build` is sent by every client that opts in; `serverBuild` is on every response. This is not new leakage; it's echoing back what both sides already publish. |
| T-29-07 | Tampering | Filter ordering (guard vs stamp) | mitigate | Guard is `IActionFilter`; stamp is `IResultFilter`. ASP.NET runs action filters BEFORE result filters by construction — the guard executes before the stamp, and a mismatched request never reaches the stamp (it short-circuits with StaleClientException). No explicit ordering hint needed. |
</threat_model>
