**CRITICAL — TS server subpath serverBuild-stamping mechanism (read before writing server.ts):**

The shipped `createAction({ currentBuild })` in `viewmodel-shell/src/server.ts` (lines ~1323-1426) captures `currentBuild` at FACTORY CREATION TIME via closure — the guard check at line 1345 (`if (currentBuild)` → `if (clientBuild !== currentBuild)`) reads the captured value, and the stamp at line 1426 (`...(currentBuild ? { serverBuild: currentBuild } : {})`) writes the captured value onto every response.

For this demo's mutable CURRENT_BUILD, that single-capture behavior is a problem: after Ashley flips build-A → build-B via the admin route, subsequent requests would still be guarded against build-A (stale capture) and would still stamp `serverBuild: "build-A"` on responses — so Scenario B (mid-session flip) silently fails to trigger detection during the tasting.

Two shipping-safe patterns exist to make the demo behave correctly. Pick the one that composes cleanest with the shipped API surface after reading `server.ts`:

**Pattern 1 — construct per-request:** inside each request handler, freshly construct the `createAction` and/or `createVersionGuard` with the current CURRENT_BUILD value, then invoke. Ensures the closure captures the current value on every call.

```typescript
if (path === "/api/shell/action") {
  const guard = createVersionGuard({ currentBuild: CURRENT_BUILD });
  const handler = createAction<DemoState>(async (payload) => { /* ... */ });
  return guard(handler)(req);
}
```

**Pattern 2 — manual stamp + wrap guard:** construct guard per-request as above, but ALSO stamp `serverBuild: CURRENT_BUILD` manually on every handler's returned ShellResponse (since `createAction`'s captured stamp is now stale). Slightly more verbose but keeps the guard construction and the response shape symmetric.

Either pattern MUST be adopted; the naïve "construct createAction once at top-of-file with `currentBuild: CURRENT_BUILD`" is silently broken for this demo. Verify by reading `viewmodel-shell/src/server.ts` lines 1323-1426 and confirming the closure-capture behavior described above before writing server.ts.

Server-side implementation notes for the demo:
- CURRENT_BUILD is a mutable server-side variable (a `let CURRENT_BUILD = "build-A";`). The admin route mutates it.
- The VMS routes wrap through createVersionGuard per Pattern 1 or Pattern 2 above.
- The `serverBuild` stamp MUST reflect the current build too — see Pattern 1/2 above.

CRITICAL: Do NOT create a fetch-shim. Do NOT re-use another demo's fetch-shim pattern for this phase. Real HTTP is load-bearing.
