**Parity fixture structure (from textnode-maxlines.json pattern):**
- `name`: fixture identifier matching the filename stem
- `endpoint` / `actionEndpoint`: `/api/probe` / `/api/probe/action`
- `steps[]`: each step has `id`, `method` ("GET" or "POST"), optional `action: { name, state? }`, `expectBodyContains: string[]`, and a `$comment` explaining the class-3 tripwire discipline

**FeatureProbeState additions (both twins, append-last per existing pattern):**

- `FilterHelperProbe string` — JSON-serialized probe payload: `{"kind":"text","operator":"contains","rawValue":"hello","displayString":"hello world","matchingHints":[],"ruleValue":"world"}`

bun side (handler.ts — FeatureProbeState interface): same fields, camelCase.

- `filter-wire-shape-one-rule-with-value` — sets FilterWireShapeProbe = "one-rule-with-value"
- `filter-wire-shape-one-rule-no-value` — sets FilterWireShapeProbe = "one-rule-no-value"
- `filter-wire-shape-two-rules-any-of` — sets FilterWireShapeProbe = "two-rules-any-of"
- `filter-wire-shape-three-rules-all-of` — sets FilterWireShapeProbe = "three-rules-all-of"
- `filter-helper-probe` — reads FilterHelperProbe JSON from state, deserializes, calls matchesFilter/MatchesFilter, sets state slot with result "true"/"false", triggers re-render

**BuildVm additions:**

Wire-shape probe: render a SectionNode "Phase 32 filter wire-shape probe" appended at the end of the page. The section renders a TableNode with ONE column carrying Filter: new FilterSpec { Kind = state.FilterWireShapeProbe branch, ... }, and the corresponding FilterDescriptor at a filterDescriptorBinds path. The emitted wire contains the FilterSpec and FilterDescriptor structures the fixture can assert on.

Helper probe: render a SectionNode "Phase 32 filter helper probe". Contains a TextNode whose value is `FilterHelperProbeResult={state.FilterHelperProbeResult}` (state slot holding "true" or "false"). The fixture asserts on this substring.

**Fixture step shape for the wire-shape probe:**
Each step posts an action to set FilterWireShapeProbe to a target branch, then the response body must contain the corresponding wire structure. Example:
- Step "one-rule-no-value": after the action, the rendered TableNode's Filter column should contain a FilterDescriptor with an is-empty rule. expectBodyContains: `['"is-empty"', 'FilterWireShapeProbe=one-rule-no-value']`. The findNulls invariant on the same step proves the is-empty rule has no "value":null.

**Fixture step shape for the helper fixture:**
Each step sends a POST with action name "filter-helper-probe" and a state blob containing the FilterHelperProbe field set to a JSON-encoded probe payload. The response body should contain `FilterHelperProbeResult=true` or `FilterHelperProbeResult=false`. Example step:
```json
{
  "id": "text-contains-match",
  "method": "POST",
  "action": {
    "name": "filter-helper-probe",
    "state": { "...existingState...", "filterHelperProbe": "{\"kind\":\"text\",\"operator\":\"contains\",\"rawValue\":\"hello world\",\"displayString\":\"hello world\",\"ruleValue\":\"world\"}" }
  },
  "expectBodyContains": ["FilterHelperProbeResult=true", "text-contains-match"]
}
```

Note: The parity fixture's action step can pass a partial state override — the harness merges with the current state. Read parity/run.ts to confirm the merge behavior before relying on it. If the harness sends the full `_state` field, the step's `state` in the fixture spec is the ENTIRE state object (not a diff) — in that case, keep a canonical "reset" state at the top of the fixture and reconstruct per step. Read the existing textnode-maxlines.json steps to understand the actual state-passing pattern.

**For the helper fixture's ~100 cases**, the fixture's steps each carry the full probe payload in the state. The probe input (kind, operator, rawValue, displayString, ruleValue, matchingHints) is embedded in the FilterHelperProbe string field. The action arm deserializes it, calls the truth function, sets the result on a state slot (FilterHelperProbeResult string — "true" or "false"), and returns the updated state. The response body contains a TextNode with value "FilterHelperProbeResult={result}", which the fixture's expectBodyContains asserts.
