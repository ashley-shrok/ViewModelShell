Difference from Plan 28-04's `demo/RichTextTasting-bun/`:
- Tasting = A/B comparison of primitives vs composite (iframe-scoped, pre-shipping).
- Verification = full-primitive walkthrough on the shipped bundle (single canvas, post-shipping, all themes).

Real-validator fetch-shim (banked lesson from Phase 21/24):
- Import the actual validator function(s) from `viewmodel-shell/src/server.ts` (grep for exports).
- In the shim's response builder, call the validator on the constructed tree BEFORE returning; if it throws / errors, log a hard failure so the page fails visibly at load rather than silently rendering an invalid tree.
- The purpose is to make sure the demo's VM cannot drift from what the real server would accept — a permissive shim hides validator bugs.

Port selection: `demo/StateAxisVerification-bun/` uses 3020; `demo/RichTextTasting-bun/` uses 3021 (Plan 28-04). Use 3022 (or first free after).
