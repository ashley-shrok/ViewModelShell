<objective>
Teach the TUI renderer that icons render as nothing, and that the 5 host `icon?:` props are ignored. This closes ICON-07.

Purpose: the TUI target is `@experimental` and explicitly not-invested-in (banked directive). Rendering SVG in a terminal isn't a v1 problem worth solving. The correct honest degradation is: TUI users see the framework's already-correct semantic content (labels, tooltips, aria-text) without the visual glyph. Zero framework maintenance cost.

Output: one `case "icon": return null;` (or equivalent no-op) in the TUI renderer's node dispatch; verification that the 5 host TUI renderers don't already touch the `icon?:` field (they shouldn't — they only read label/children, so the field is silently ignored by omission — but verify).

**Design of record:** `.planning/design/icons-primitive.md` §9.

**No unicode-fallback mapping.** Per design-doc §9 and CONTEXT.md constraints. Do NOT add a `Record<IconName, string>` map from icon names to emoji or box-drawing characters. That's deferred to a hypothetical v2 IF the TUI investment ever returns.
</objective>

If Plan 09's tailnet verification page needs a "TUI icons someday?" note, that's a bounty, not a scope change.
- **`case "icon": return null` is defensive against future ViewNode-union churn.** Even if the current TUI `default:` returns null (making the explicit case functionally redundant), the explicit case is discoverable via grep and documents the intent. Do NOT rely on the default.
