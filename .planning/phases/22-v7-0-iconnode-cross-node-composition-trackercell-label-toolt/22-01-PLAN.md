<objective>
Declare the icons wire surface on the TypeScript backend (the source of truth the .NET twin mirrors) and teach the TS tree-validator that an icon-only ButtonNode without a tooltip is a tree-validation failure.

Purpose: nothing else in this phase can be built against a shape that doesn't exist. And the a11y discipline (icon-only-button REQUIRES tooltip) is a property of the WALKER + the TYPE's TSDoc before it is a property of any renderer — if the type doesn't say "decorative vs meaning-carrying dispatches on `label` presence" and the walker doesn't reject icon-only-without-tooltip, the next implementer ships a screen-reader void silently.

Output: `IconName` closed union of ~102 members (design-doc §6); `IconNode` interface with the field set from design-doc §3; `IconNode` added to the `ViewNode` union at index.ts:118-160; five host interfaces (`ButtonNode`, `LinkNode`, `SectionNode`, `BadgeNode`, `ListItemNode`) each get an `icon?: IconName` field with TSDoc pointing at design-doc §4; the icon-only-button rule wired into `server.ts`'s existing tree-validator walker; vitests proving both the wire shape and the walker's FAIL-before / PASS-after by mutation.

**Design of record:** `.planning/design/icons-primitive.md` §3, §4, §5, §6, §8. Read in full before touching a line.
</objective>
