<risk_summary>
- **SVG namespace pitfall.** `document.createElement("svg")` produces an HTML element that renders as nothing in browsers. Icons MUST use `createElementNS("http://www.w3.org/2000/svg", "svg")`. jsdom may forgive this in tests but real browsers won't. The test case for "the rendered svg has viewBox=... and paths inside" is the tripwire; add an assertion that inspects the element's `.namespaceURI` if jsdom is lenient enough to pass without it.
- **Icon-only-button a11y integration.** The design says: the button's `tooltip` becomes its `aria-label` (design-doc §5). The button() renderer already handles tooltip → data-vms-tooltip via the TOOL-01 infrastructure (6.12.0). Verify the button already sets `aria-label` from tooltip when label is empty; if not, an ancillary fix in button() is required. Task 22-04-05 case 4 is the tripwire.
- **Bundle size.** The `ICONS` payload adds ~50KB uncompressed / a few KB gzipped to the browser bundle. This is the design-doc §6 acceptable cost. If a size regression check trips CI, note in the plan summary but do NOT strip icons — the whole point of bundling is the wire carries only names.
- **Ordering: icon emission BEFORE label.** The design-doc §4 fixes icon as LEADING (before the label). Reversing to trailing would break the Hestia card layout. Task 22-04-05 cases 3 + 5 + 6 verify the icon SVG appears in DOM order BEFORE the host's label text.
