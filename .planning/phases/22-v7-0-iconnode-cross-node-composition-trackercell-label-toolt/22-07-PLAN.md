<risk_summary>
- **Byte-identical mirror discipline.** The `iconsSection` on bun and the equivalent .NET emission MUST produce identical JSON. Order of children matters; field ordering inside each node matters (STJ + JSON.stringify emit in property declaration order — verify the .NET record parameter order matches the TS interface field order for IconNode). If parity flags a diff, fix by making the two sides match, NOT by adjusting `compareIgnoreFields` (that would silence the very drift the gate exists to catch).
- **Vacuous coverage is worse than no coverage.** A fixture step that RUNS but whose branch doesn't emit the expected substring produces a byte-diff-agreement (both backends emit "nothing") over a real drift. `expectBodyContains` is the invariant that stops this. If Task 22-07-05 shows a green run BUT the `expectBodyContains` array is missing an entry from Task 22-07-04's list, the run is a false green.
- **`icon-only-invalid` action MUST run through the walker.** If the bun handler's `createAction` wrapper doesn't call `.Validate()` on the returned tree, the invalid_tree response never fires — the tree just renders as normal. Verify the response goes through the validator; if not, add an explicit `.Validate()` call (matching the .NET twin's `.Validate()` chain).
- **`export PATH=$HOME/.dotnet:$PATH` is not optional.** The parity harness dies with a bare `spawn` stack trace naming no cause if `dotnet` isn't on PATH. AGENTS.md gotcha for §9 documents this; the plan's verification step has it explicitly.
</risk_summary>
