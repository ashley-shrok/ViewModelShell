<objective>
Add a `weight` axis to `TextNode` — the semi-bold body-size weight variant that row primaries (`ListRowNode.primary`, `MessageNode.author`, `UserRowNode.name`, `SettingRowNode.label` in Phase 24-25) need. **Design decision: Option A (new orthogonal `weight` field), NOT Option B (`style: "strong"` extension).**

**Rationale for Option A** (per the design authority granted by CONTEXT.md §Decisions 2):
- **Composability** — a `style: "body"` TextNode needs to become `weight: "medium"` without stopping being body-typed. Option B forces the same result through style-value overloading, which conflates typographic role (heading / body / muted / caption) with weight (medium / bold). The precedent this framework already ships is `tone` — an ORTHOGONAL semantic-color axis alongside `style` (per PATTERNS.md §1: TextNode.tone at index.ts:1001 is exactly the analog). Mirroring that pattern for weight keeps `style` on one job (typographic role) and puts weight on its own axis, matching Chakra/MUI/Ant's `fontWeight` prop shape and every server-driven peer's typography vocabulary.
- **Wire surface cost** — one new optional field vs one new closed-union value. The new field IS marginally more surface, but every closed union in this framework is closed-enum-must-be-enum on .NET already (per AGENTS.md), so both shapes require a new .NET enum. The differentiator is on the TS side: Option B slightly conflates the `style` enum's semantics; Option A cleanly separates axes.
- **Future-proofing** — the third weight (bold, 700) is already needed for a `SectionNode` heading-like emphasis. Option B locked in "strong" as one value; Option A lets us ship 3 values (regular / medium / bold) with the same wire surface cost.

Purpose: The semi-bold weight anchor points that primary-slot row typography needs, expressed orthogonally to `style` so composites can freely compose typographic role + weight.
Output: `TextNode` gains a `weight` axis on both backends; three CSS rules ship; render + serialization tests are green with mutation proof.
</objective>
