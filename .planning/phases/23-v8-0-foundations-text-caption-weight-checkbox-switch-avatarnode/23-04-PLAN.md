    (b) ADD a new `private avatar()` method (place it near `private icon()` at :4143). Exact implementation (per PATTERNS.md §6 — matches CONTEXT.md §4 priority table verbatim):

    ```typescript
    private avatar(n: AvatarNode, parent: HTMLElement): void {
      const size = n.size ?? "md";

      // Image mode — <img> element. img displaces the background; alt="" is legal.
      if (n.image != null && n.image !== "") {
        const img = document.createElement("img");
        img.className = `vms-avatar vms-avatar--${size}`;
        img.src = n.image;
        img.alt = n.alt ?? "";
        parent.appendChild(img);
        return;
      }

      // Non-image modes render as <div role="img"> with a computed aria-label
      // per the CONTEXT §4 priority table.
      const el = document.createElement("div");
      const classes = ["vms-avatar", `vms-avatar--${size}`];
      if (n.tone) classes.push(`vms-avatar--${n.tone}`);

      if (n.initials != null && n.initials !== "") {
        el.className = classes.join(" ");
        el.setAttribute("role", "img");
        el.setAttribute("aria-label", n.alt ?? n.initials);
        el.textContent = n.initials;
      } else if (n.icon != null) {
        classes.push("vms-avatar--icon");
        el.className = classes.join(" ");
        el.setAttribute("role", "img");
        el.setAttribute("aria-label", n.alt ?? "");
        // v7.0.0 icon renderer reused — the circle background carries the tone,
        // not the icon stroke (tone=undefined); aria-label is on the outer div (label=undefined).
        el.appendChild(this.renderIconSvg(n.icon, size === "sm" ? "sm" : "md", undefined, undefined));
      } else {
        el.className = classes.join(" ");
        el.setAttribute("role", "img");
        el.setAttribute("aria-label", n.alt ?? "");
      }

      parent.appendChild(el);
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → client render (image URL) | `AvatarNode.image` is a URL string that renders as `<img src="{url}">`. The URL comes from the server-driven view tree — it's authored by the app, not user input crossing into the DOM. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-04-01 | Information Disclosure | `AvatarNode.image` — image URL rendered as `<img src>` | accept | The URL is server-authored (comes from the app's `buildVm` output). An app that puts a hostile URL into an avatar is a defect of that app, not this primitive; the framework's job is to render what the tree says. The `<img>` element is a passive fetch — no script execution, no CORS credentials leak beyond what the app's own fetches would incur. This is byte-identical to what `LinkNode.href` and any other URL field on the wire already does; no new attack surface. |
| T-23-04-02 | Spoofing (avatar hijack) | `AvatarNode.initials` / `alt` — user-facing string | accept | Both are string content, rendered as `textContent` (not `innerHTML`) or as `aria-label` — no HTML injection possible via `textContent`. A hostile server can make the avatar look like anyone by setting initials/tone — but a hostile server can already make ANY node in the tree misleading; this is not unique to AvatarNode and is out of scope for framework-level mitigation. |
| T-23-04-03 | Tracking pixel via image | `AvatarNode.image` as an unfamiliar-origin URL | accept | Standard `<img>` fetch, no cookies attached to cross-origin by default beyond browser policy. The app that authored the tree is responsible for what URLs it emits (same as `LinkNode.href` or any other URL). Framework doesn't proxy or sanitize URLs — that would break legitimate CDN patterns. |

All three threats resolve to "accept — no new surface beyond what other URL-bearing / user-facing-string wire fields already ship with." The framework's contract is that the server is trusted to emit sensible trees; this primitive doesn't change that.

**Note:** the closed enums `AvatarSize` and `Tone` on .NET, and the closed union in TS, prevent a server from emitting an unknown value — bad values fail the tree-validator loudly (per AGENTS.md's "nothing important fails quietly" rule).
