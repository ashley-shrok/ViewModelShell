    **Section 1 — Thesis: Route A + Route B.** Explain the two-track structure the framework carries:
    - **Route A** = primitive axes (tone/emphasis/size/state/layout/density) + open composition. What VMS ships today. Consumers with shape-variance drop to primitives and compose.
    - **Route B** = pre-made composite recipes with typed slots. What v8.0.0 adds. Recipes own layout/typography/spacing for shapes with shared visual convention.
    - Both coexist. Recipes never DEPRECATE primitives.

    **Section 2 — Governance rule: earn a composite.** State the rule Ashley canonicalized 2026-07-29 (per CONTEXT.md §7):
    - A shape earns a composite when the best-effort with today's primitives is a "pretty bad approximation" of the common shape.
    - Bar is VISUAL — the "after" has to look right; the "before" has to look wrong enough to justify the primitive earning a promotion.
    - Judgment per shape; eyeballed against a served tasting before it earns the composite.
    - Two failure modes to guard against:
      - **Bloated grab-bag** — recipes that don't earn their weight (fix: high bar for new recipes; every proposed recipe requires a served tasting).
      - **Too-rigid recipe** — a recipe that boxes in the consumer (fix: typed slots stay unconstrained-content ViewNode subtrees; axes stay closed enums so variance is expressed by the axis, not by escape-hatch fields).
    - The precedent: MUI `ListItemText`, Ant `List.Item.Meta`, Chakra `Card` composites, Phoenix LiveView function-component slots, Blazor Razor typed content. Every server-driven peer surveyed ships this layer.

    **Section 3 — The typed-slots pattern.** State the shape every composite obeys:
    - Typed slots with semantic names: `leading?`, `primary` (or `heading`), `secondary?` (or `description?`), `meta?`, `trailing?`, plus axes `tone?`, `state?`.
    - Each slot accepts a full ViewNode subtree — apps drop any node they want (text, badge, icon, button, avatar, checkbox) into any slot.
    - The recipe owns the shape: DOM layout, typography (which slot uses which text style/weight), spacing (gap, padding, alignment).
    - Variance is expressed through CLOSED-ENUM axes (`tone: Tone`, `state: string`), not raw CSS or free-form fields.
    - This split — typed slots + closed enums + unconstrained-content nesting — is the survey-consensus shape across all peer frameworks. Framework owns the recipe; app owns the content.

    **Section 4 — Milestone inventory: 10 composites + 3 wire tweaks.**
    The approved set (per the tasting served 2026-07-29, ROADMAP.md v8.0.0 block):

    *Wire tweaks (Phase 23 foundations):*
    1. `TextNode.style: "caption"` — 3rd typographic tier (text-xs, muted, opacity 0.85). COMP-01.
    2. `TextNode` weight axis — semi-bold body-size weight (Option A: new orthogonal `weight?: "regular"|"medium"|"bold"` field). COMP-02.
    3. `CheckboxNode.variant: "switch"` — visual switch-slider render mode; wire semantics unchanged. COMP-03.
    4. `AvatarNode` — new standalone primitive (image > initials > icon > empty; sm/md/lg/xl; tone axis). COMP-04. (Technically a new node, but sized here as a "foundation" the composites consume rather than a composite itself.)

    *Composites (Phase 24-25):* For each, name it + list its typed slots. Use the schemas from the tasting page as the source of truth (read them from the HTML file). List:
    - `ListRowNode` (Phase 24) — `leading?, primary, secondary?, meta?[], trailing?, action?, tone?, state?`.
    - `MessageNode` (Phase 24) — `avatar?, author, timestamp?, body, actions?[], tone?, state?`.
    - `AlertNode` (Phase 24) — `heading, body?, icon?, tone, dismissible?, actions?[]`.
    - `EmptyStateNode` (Phase 24) — `illustration?, heading, description?, primaryAction?, secondaryAction?, tone?`.
    - `UserRowNode` (Phase 25) — `avatar, name, role?, presence?, actions?[]`.
    - `DetailRowNode` (Phase 25) — `label, value, tone?, action?`.
    - `TimelineEntryNode` (Phase 25) — `time, icon?, tone?, heading, body?`.
    - `SettingRowNode` (Phase 25) — `label, description?, control (CheckboxNode + variant:"switch" typical)`.
    - `ChipNode` + `ChipListNode` (Phase 25) — Chip: `label, leading?, tone?, emphasis?, removable?, action?, removeAction?`; ChipList: `chips[], layout?`.

    Confirm each schema by reading the tasting-page HTML — the tasting is the canonical source at doc-writing time.

    **Section 5 — Layered adoption order.**
    - **Phase 23 (foundations):** 4 wire tweaks + AvatarNode (this phase). Batch-then-ship (no release).
    - **Phase 24 (primary composites):** ListRow, Message, Alert, EmptyState — the high-frequency shapes.
    - **Phase 25 (secondary composites):** UserRow, DetailRow, Timeline, SettingRow, Chip + ChipList — deeper cuts.
    - **Phase 26 (adoption + release):** wider demo adoption + comprehensive tailnet verification page + aligned v8.0.0 npm + NuGet release.

    Justify the order: foundations first because every downstream composite consumes them; primary composites before secondary because they cover the highest-frequency shapes; adoption + release last because a comprehensive verification page needs the full set in place.

    **Section 6 — Conventions the milestone follows.**
    - **Fleet-adoption discipline** — every composite ships WITH real demo adoption in the same batch (banked from `UseVmsShellStaticFiles` 6.7.0 fire).
    - **Parity FeatureProbe extension** — every composite grows `buildVm` in all 3 backends + `expectBodyContains` tripwire per branch (banked from 6.0.0 seeded-helpdesk fix; a diff can only prove things about code it actually RUNS).
    - **AA-contrast hand-check per new fg/bg pair** — the fixed 13-pair `check:aa-contrast` gate does NOT auto-cover new pairs (banked from 3.5.0 toast fix); each composite's new pairs get hand-checked across default + 12 themes.
    - **Closed-union-must-be-enum on .NET** — every closed union in the new composites is a real .NET enum (not `string?`) with a `KebabEnum<T>` converter (per AGENTS.md maintainer rule, banked from 6.0.0 migration).
    - **WhenWritingNull on every nullable, WhenWritingDefault on optional non-nullable bools** — gotcha #8 non-negotiable.
    - **Batch-then-ship** — CHANGELOG entries accumulate under "Unreleased" during Phases 23-25; v8.0.0 publishes at Phase 26 closeout with all 10 composites + 3 wire tweaks + 4 foundations in one aligned release. Rationale: coherence of the milestone story to consumers.
    - **Route A / Route B coexistence** — recipes never deprecate primitives; consumers with unforeseen shapes drop back to primitives.
    - **The @experimental TUI target** drops the composites entirely for v1 (not-invested-in per standing directive).

    **Section 7 — Design open questions (deferred to per-phase plans).**
